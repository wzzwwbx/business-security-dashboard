# 业务系统数据接入与态势设计台账

> 本文档是业务安全态势系统的持续维护台账。后续每接收到一个业务系统的资料、接口说明、字段样例或访谈结论，都先登记到本文档，再据此确定数据模型、接入适配器和态势展示元素。
>
> 文档状态：持续维护  
> 首次建立：2026-07-29  
> 当前原则：已确认事实、待确认信息、设计假设分开记录。

## 1. 使用规则

### 1.1 信息状态

| 状态 | 含义 |
| --- | --- |
| 已确认 | 已由对方资料、实际接口、样例数据或现场验证证明 |
| 待确认 | 需要向来源系统或相关负责人补充确认 |
| 设计假设 | 为推进建模或原型暂时采用的假设，不代表来源系统承诺提供 |
| 不提供 | 已确认来源系统没有该能力或当前阶段不开放 |
| 已验证 | 已完成联调、解析、入库或展示验证 |

### 1.2 记录原则

1. 不把页面上的 Mock 数据当作外部系统真实能力。
2. 每个指标必须能够追溯到来源系统、原始字段、统计口径和时间范围。
3. 原始数据保留来源标识、请求/批次标识、采集时间和 schema 版本，便于重放与审计。
4. 业务系统的原始字段先进入接入适配层，再归一到态势领域模型；前端不直接绑定上游原始格式。
5. 涉及人员、手机号、账号、位置、日志等敏感数据时，记录脱敏、授权、留存和审计要求。
6. 数据不足时，展示“暂无数据/覆盖未知/来源异常”，不使用看似精确的默认值掩盖缺口。

## 2. 当前系统边界

### 2.1 已有展示域

| 展示域 | 路由 | 当前定位 | 后续重点数据 |
| --- | --- | --- | --- |
| 综合态势 | `/overview` | 汇总业务、安全、终端和运维状态 | 跨域 KPI、重点事件、综合风险、数据来源健康 |
| 安全态势 | `/security` | 展示安全事件、防护、策略和风险 | 审计、零信任、规则引擎、漏洞/告警、防护覆盖 |
| 业务态势 | `/business` | 展示关键业务连续性和链路质量 | 服务、接口、交易、队列、数据库、SLA |
| 终端态势 | `/terminal` | 展示终端资产、人员、健康和风险 | MDM、USB Key、证书、补丁、位置、人员主数据 |
| 运维态势 | `/ops` | 已形成真实多源运维闭环 | 主机、资源、进程、网络、来源健康、运维告警 |

### 2.2 已有接入链路

```text
业务系统 / 安全系统 / 终端系统 / 运维来源
        -> 接入适配器或统一外部入口
        -> 字段校验、标准化、身份与资产归一
        -> 原始数据留存 + 主题数据聚合
        -> /api/situation/** 或 /api/ops/**
        -> 态势页面与详情/事件流
```

当前工程已有：

- `/api/ops/ingest/probe`：探针严格字段接入；
- `/api/ops/ingest/external`：外部系统灵活 envelope 接入占位；
- `/api/ops/ingest/manual`：人工导入/联调用入口；
- `/api/situation/**`：综合、安全、业务、终端主题态势统一查询契约，当前主要由 Mock/占位数据支撑。

## 4. 系统详细档案

### 4.1 SYS-001：Linux Java Probe

| 项目 | 内容 |
| --- | --- |
| 定位 | Linux 主机运维采集来源 |
| 信息状态 | 已验证（工程已实现），具体部署覆盖待补充 |
| 采集对象 | 主机基础信息、资源快照、网络接口、进程 |
| 接入接口 | `POST /api/ops/ingest/probe` |
| 认证 | `X-Agent-Key`、`X-Timestamp`、`X-Signature`，HMAC-SHA256 |
| 时间字段 | `observedAt`，使用带时区 ISO-8601 |
| 可靠性 | 探针本地 spool 缓冲，后端恢复后补报 |
| 归一标识 | 内部 `host_code` + 外部 `external_asset_id` |

已确认字段范围：

- `host`：`hostCode`、`hostname`、`displayName`、`primaryIp`、`osName`、`kernelVersion`、`arch`、`cpuCores`、`memoryTotalBytes`、`machineFingerprint`；
- `snapshot`：CPU、load、内存、swap、磁盘、TCP established、进程数量；
- `networkInterfaces[]`：网卡信息；
- `processes[]`：进程信息。

可形成的展示：主机在线/陈旧/离线、资源趋势、TopN 进程、网络接口、运维告警、来源健康。部署数量、采样周期、字段完整率和数据保留周期待确认。

#### 对态势系统的设计映射

当前只登记设计方向，待拿到字段样例后再确定组件和指标：

- **业务态势**：签批总量与趋势、签批处理时效、待签批/流转积压、接收与发送量、文件流转成功率、签阅服务可用性。
- **安全态势**：异常时段登录、异常下载、频繁解密、本地导入后外发、登录终端与人员不匹配等复合事件。
- **终端态势**：APP 安装/在线覆盖、终端活跃度、终端上的加密/解密行为、按人员和终端聚合的操作风险。
- **综合态势**：签阅系统当前活跃度、签批链路健康度、重点风险事件和来源数据健康状态。

#### 当前明确的限制

- 目前只知道“能记录哪些行为”，不知道每类日志能否提供成功/失败、文件标识、人员标识、终端标识、来源/目标、错误原因和耗时。
- 在字段和统计口径确认前，不把 Mock 中已有的签批时延、队列、事件数量等数值视为签阅系统真实数据。
- 文件名、文件内容摘要、人员、账号、终端标识可能涉及敏感信息，需先确认脱敏、加密、留存和查看权限。

### 5.1 推荐最小公共字段

所有来源尽量提供：`sourceSystem`、`schemaVersion`、`requestId`/`batchId`、`eventId`（如适用）、`observedAt`、`receivedAt`、对象外部 ID、对象类型、状态、原始更新时间。无法提供的字段要明确写出原因，不通过默认值填充。

### 5.2 推荐事件字段

事件类数据优先确认：事件 ID、事件类型、发生时间、发现时间、恢复时间、等级、状态、对象 ID、来源 IP/设备/账号（按权限处理）、描述、证据引用、处置人、处置动作、处置结果和关联事件 ID。
