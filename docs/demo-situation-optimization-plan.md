# 综合态势与业务态势演示优化方案

## 1. 背景与目标

下周演示重点展示终端、密信、签阅和境外通信态势。当前没有真实业务数据，本轮使用结构完整、口径闭合且可重复的模拟场景，优先优化：

- 综合态势：人员、装备、位置、业务活动和境外通信的一体化总览；
- 业务态势：密信、签阅和 50 Mbps 境外通信专题；
- 终端下钻：从国家聚合点进入人员装备套件详情。

演示模式只显示“综合态势”和“业务态势”两个主导航入口。安全、终端、运维和系统管理能力不删除，后续可恢复显示。

## 2. 已确认边界

| 项目 | 结论 |
| --- | --- |
| 业务名称 | 签阅 |
| 境外通信带宽 | 50 Mbps |
| 人员范围 | 已配发装备人员，共 20 名模拟人员 |
| 数据状态 | 全部为模拟数据，静态展示 |
| 地图精度 | 国家级；北京单独作为境内中心点 |
| 单人装备套件 | PAD、密盒、密信软件、签阅软件、卫星终端 |
| 数据接入 | 当前无真实来源，后续按实际接口替换模拟提供层 |

本方案默认 50 Mbps 是境外终端共享的一条双向通信链路。上下行分别按 50 Mbps 容量计算，链路利用率取 `max(上行速率, 下行速率) / 50 Mbps`。

## 3. 演示信息架构

### 3.1 综合态势

综合态势回答以下问题：

1. 配发装备人员有多少，当前多少人在线；
2. 人员分布在哪些国家，各区域状态如何；
3. 每名人员的 PAD、密盒、业务软件和卫星终端是否可用；
4. 密信和签阅当前开展了多少业务；
5. 50 Mbps 境外链路当前流量和利用率如何。

页面以世界地图为主视觉：

- 国家点位显示“在线人数 / 配发人数”；
- 北京作为境内通信中心，连接各境外国家；
- 连线颜色表示链路状态，视觉宽度表示流量级别；
- 点击国家点位显示该国人员及终端列表；
- 点击列表中的终端打开用户装备套件详情；
- 不展示虚假的终端精确经纬度。

顶部核心指标：

- 配发装备人员：20 人；
- 当前在线用户：15 人；
- 完整套件就绪：14 套；
- 境外链路利用率：37.2%。

地图周边展示装备状态、密信/签阅摘要、实时业务事件以及境外通信趋势。

### 3.2 业务态势

业务态势使用三个专题维度：

- 密信态势：当前登录、登录/登出、消息收发、文件收发、分时趋势和国家排行；
- 签阅态势：收到、已处理、待处理、异常/退回、处理趋势和国家排行；
- 境外通联：50 Mbps 容量、上下行速率、利用率、累计流量、峰值和国家流量占比。

密信和签阅的汇总关系必须闭合：

```text
密信登录 18 - 登出 3 = 当前登录 15
签阅收到 68 = 已处理 54 + 待处理 11 + 异常/退回 3
```

### 3.3 用户装备详情

每名人员固定关联一套装备：

```text
人员
├── 终端 PAD
├── 密盒
├── 密信软件
├── 签阅软件
└── 卫星终端
```

详情抽屉展示：

- 人员概况：模拟姓名、人员编号、部门、所在国家、在线状态和最后活动；
- 装备套件：PAD、密盒和卫星终端的状态、版本及最后心跳；
- 业务软件：密信登录状态、签阅运行状态、版本和今日活动；
- 最近活动：登录、登出、消息/文件收发、打开、签批和加解密事件。

“用户在线”“终端在线”和“套件可用”分别定义，不能混为同一指标。

## 5. 模拟数据原则

1. 建立单一、强类型的演示场景，所有汇总指标由 20 名人员明细派生；
2. 人员、PAD、密盒、软件、卫星终端和业务事件均使用稳定 ID；
3. 使用真实格式的虚构姓名、编号、版本、IP 和事件描述；
4. 事件时间相对页面加载时间生成，避免演示日期过期；
5. 页面显示“模拟数据”和更新时间，不将模拟值表述为真实来源；
6. 预设正常、降级和离线状态，使演示具有可解释的层次；
7. 后续真实接入只替换数据提供层，不改页面领域模型和主要交互。

## 6. 实施步骤

1. 增加演示模式和可见页面配置，只显示综合态势、业务态势；
2. 建立统一模拟场景、派生统计和一致性测试；
3. 改造综合态势地图、国家下钻和装备详情抽屉；

6. 演示完成后，根据真实数据接口逐项替换模拟数据。

### 8.23 2026-08-11 第十八轮修订：卫星线路点不到问题的根因与修复

1. **根因一（命中层缺失弧度）**：卫星命中层 `lineStyle` 被整体替换为 `{width, opacity}`，丢失 `curveness`，命中层退化为直线，弯曲的可见弧线处点不到；修复为继承原 lineStyle；
2. **根因二（ECharts 贝塞尔命中退化为包围盒）**：`lines` + `curveness` 的命中检测按包围盒，巴西上行弧线的大包围盒覆盖肯尼亚弧线上半段，点击肯尼亚线路会误开巴西面板；且卫星元素不携带 `__ecData`，无法反查业务数据；
3. **根因三（geo 控制点公式与渲染不一致）**：实测 ECharts 对 geo 坐标系 lines 的贝塞尔控制点是在端点投影到屏幕后、按屏幕端点 + linesLayout 公式（`cpx=mx+(y1−y0)·c, cpy=my−(x1−x0)·c`）重新计算，任何 geo 空间公式的离散点都与实际弧线偏差 13px 以上；
4. **根因四（ECharts click 清空面板）**：地图区域点击会触发 ECharts click，`handleClick` 开头把 `topologyCountry` 置空，把 zr 线路命中刚打开的面板清掉；修复为仅 scatter 命中时处理，地图区域点击交由自定义线路判定；
5. **最终方案：完全绕开 ECharts 内置命中**——`convertToPixel` 投影 geo 端点，屏幕空间按 ECharts 公式离散弧线，用点到折线距离（8px 阈值）判定命中；线路保持 `silent`，zr 层自定义 click/mousemove（卫星图标、站点圆点优先 scatter，点击卫星图标直接打开该卫星服务路由拓扑）；命中率约 70%，失败点均在站点圆点/卫星图标附近（有意 scatter 优先），线路主体可点；悬浮任一段高亮整条路由。
